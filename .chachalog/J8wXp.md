Mutations that operate on many nodes at once are now bounded by a dedicated configuration property, `graphql.mutation.batch.limit` (default `5000`, `0` disables). Previously `mutateNodesByQuery`, `mutateNodes` and `addNodesBatch` had no bound: `mutateNodesByQuery`'s `limit` argument was optional, and the two batch fields processed however many entries the caller supplied. A mutation batch is sized separately from the read-side `graphql.fields.node.limit` because its work is different — pending changes accumulate in one JCR session and are written in a single commit — so the two can now be tuned independently. Like the other limits, this one is only accepted from the default configuration file, so a non-default configuration cannot loosen it. It is a separate concern from the existing query-cost guards, which measure the shape of a document rather than how many items its arguments carry.

Where the bound is enforced follows from what is knowable before a request executes. An **enumerated** batch states its size in an argument, so it is measured across the whole document before execution and **rejected** when the total exceeds the limit — measuring the whole document is what keeps the bound from being multiplied by aliasing the same mutation several times, each call individually within the limit. Rejecting rather than truncating is deliberate: the caller named those nodes, so operating on a prefix of the list would quietly not do what was asked. **`mutateNodesByQuery`** cannot be measured that way, because how many nodes a JCR-SQL2 statement matches is not known until it runs, so it is bounded when the query executes and **truncates** instead, with an explicit `limit` argument honoured but never raising the result set above the configured value.

**Are you affected?** Only if a single request operates on more than 5000 nodes — the default matches the existing node limit, so ordinary traffic is unchanged. If it does, either split the work into smaller requests (using `limit`/`offset` for `mutateNodesByQuery`), or raise `graphql.mutation.batch.limit` in `org.jahia.modules.graphql.provider-default.cfg`.
